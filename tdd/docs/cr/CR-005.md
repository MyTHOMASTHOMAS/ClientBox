## 2. Bilan de l'exploration technique directe du binaire `claude`

L'exécution des commandes d'inspection `which claude`, `claude -v` et `claude -h` sur l'environnement hôte a permis de caractériser formellement le binaire installé sans émettre de prompt (préservation des quotas et indépendance vis-à-vis des tokens d'authentification) :

| Composant / Comportement | Constat technique dans le terminal hôte | Décision d'ingénierie ClientsBox |
|---|---|---|
| **Version installée** | `2.1.330 (Claude Code)`. | Adaptateur ciblé sur les contrats de Claude Code v2+. |
| **Localisation du binaire** | Présent sous `/home/thomaz/.local/bin/claude`. | Résolution exclusive via la variable d'environnement `CLAUDE_CLI_BIN` per `SPEC-ARCH-03` (sans fallback hasardeux sur le PATH). |
| **Mode non interactif (headless)** | Drapeaux `-p`, `--print` (« Print response and exit, useful for pipes »). Ignore automatiquement la boîte de dialogue de confiance du workspace. | `buildCommand` utilise systématiquement `--print` pour tous les Runs de blocs. |
| **Format du flux de sortie** | Option `--output-format <format>` acceptant `"text"`, `"json"`, ou `"stream-json"`. Associée obligatoirement à `--verbose` pour émettre les métadonnées de session, et `--include-partial-messages` pour le streaming de deltas en temps réel. | Utilisation systématique de `--output-format stream-json --verbose --include-partial-messages` pour un streaming temps réel fluide d'événements JSON ligne par ligne (aligné sur Antigravity et Codex). |
| **Gestion et attribution de session** | Le flux stream-json émet dès la 1ʳᵉ ligne un événement `{"type":"system","subtype":"init","session_id":"<id>"}`. | Capture paresseuse (*lazy capture*) via `extractSessionId` dès le premier Run, sans prompt d'amorce interactif ni génération d'UUID côté hôte. Enregistrement direct dans `ScenarioSessionRegistry`. |
| **Reprise de session** | Options `-r <id>`, `--resume <session-id>` (« Resume a conversation by session ID or name »). | Si `ctx.sessionId` est présent (Runs subséquents), `buildCommand` génère l'option de reprise exclusive `--resume <ctx.sessionId>` pour maintenir le fil contextuel. |
| **Bypass des approbations interactives** | Drapeau `--dangerously-skip-permissions` (« Bypass all permission checks »). | Injection systématique en exécution automatisée de scénario pour éviter tout blocage interactif en cours de Run. |
| **Sélection du modèle d'IA** | Option `--model <model>` acceptant les alias (`sonnet`, `opus`, `haiku`, `fable`) ou identifiants complets. | Injection conditionnelle de `--model <ctx.model.trim()>` lorsque le modèle est spécifié dans le profil ou l'agent. |
| **Absence de jeton / mode test** | Le client n'a pas de token configuré ; les prompts réels échouent sans authentification. | Conception d'un mock déterministe de test (`scripts/mock/mock-claude.*`) pour la suite CI et les tests unitaires sans dépendance externe. |

## 4. Ce que nous n'avons pas demandé

- L'authentification interactive au runtime (l'utilisateur doit avoir configuré au préalable son accès Claude Code sur la machine hôte via `claude login` ou les variables d'environnement API d'Anthropic).
- L'émission de prompts réels vers l'API Anthropic lors des tests automatisés du projet (recours exclusif au mock `mock-claude`).
- L'installation automatique du CLI Claude ou de ses dépendances système (ClientsBox vérifie l'existence et l'exécutabilité du binaire désigné par `CLAUDE_CLI_BIN` sans tenter d'installation silencieuse).
- La modification du moteur de graphe, du Join ou des autres types de blocs (l'adaptateur s'insère strictement dans le contrat `CLIAdapter` sans impact sur le domaine d'orchestration).

## 5. Reformulation

Le client demande l'intégration officielle d'un **quatrième adaptateur opérationnel** dans ClientsBox : le **CLI de Claude** (`claude-cli` / Claude Code version 2.1+), venant compléter `cursor-cli`, `antigravity` et `codex-cli` :

### 1. Isolation système et configuration dynamique (`CLAUDE_CLI_BIN`)
* Résolution étanche du binaire via la variable d'environnement `CLAUDE_CLI_BIN` (dans `env/.env`, `env/.env.example` et `env/.env.test`).
* Validation stricte d'existence et de permissions d'exécution au démarrage via `src/lib/process/env/` : `CLAUDE_CLI_BIN` devient le **4ᵉ binaire d'agent obligatoire** au boot (`isRequired: true`, `SPEC-SRV-01`).

### 2. Implémentation du contrat `CLIAdapter` (`claude-cli`)
* Création des modules `ClaudeCLIAdapter` (`LIB-033`), `claude-session.helper.ts` (`LIB-034`) et `claude-stream.extractor.ts` (`LIB-035`) dans `src/lib/adapters/claude/`, portant le catalogue officiel des modules signés de **197 à 200** (`SPEC-ARCH-08`).
* Construction des commandes non interactives via `claude --print --output-format stream-json --verbose --include-partial-messages --dangerously-skip-permissions` (mode initial, sans session) et `claude --resume <sessionId> ...` (mode reprise avec session).
* Gestion du modèle IA optionnel via `--model <model>` (alias ou nom explicite).

### 3. Streaming résilient et découplage des payloads
* Décodage robuste des flux JSONL au fil de l'eau (`parseStreamLine`) pour le terminal live (support des deltas de texte).
* Extraction textuelle stricte (`parseOutput`) pour garantir la pureté des données transmises aux blocs `If` et `exit`.
* Capture de session fluide par écoute de l'événement d'initialisation (`extractSessionId`) sans émission de ping au runtime.

### 4. Découverte des modèles et intégration IHM
* Énumération des modèles supportés via `listModels()`, protégée par cache mémoire LRU (`ADR-016`).
* Disponibilité immédiate de l'option « Claude CLI » (`claude-cli`) dans le formulaire d'agent et validation des profils associés.
